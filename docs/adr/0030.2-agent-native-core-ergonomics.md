# 0030.2. Agent-Native Core Ergonomics — Primitive Audit, Certified Invariants, and Sidestep Decisions

**Date**: 2026-08-09
**Status**: Proposed
**Depends on**: [0030-agent-native-authoring](./0030-agent-native-authoring.md), [0030.1-agent-native-gap-audit](./0030.1-agent-native-gap-audit.md) — graduates work from [0025](./0025-core-proposals-from-ui.md)'s open items

## Context

0030.1 audited the *instrumentation around* the framework. The maintainer's
challenge went deeper: every ergonomic surface of the framework **itself**
can be analyzed and potentially improved with novel ideas — sidestepping
entire problem classes with better architecture, which requires deep
understanding of our source, our recorded pain, and the industry's.

Method: five primitive-level audits (reactivity, component model, template
engine, composition/lifecycle/DI, async), each reading the nisli source
line-by-line, the in-repo record (`docs/issues/`, ADRs 0005/0008/0015/0023/
0025/0028), and the industry's recorded failure modes for that primitive
class. The caliber bar is the house's own sidestep lineage: ADR 0015
*deleted* `batch()` by making coalescing automatic; ADR 0023 made
disconnect/move bugs unrepresentable; `resource()` (0028) made stale-async
overwrites impossible. Twenty-eight proposals came back; this ADR is the
curation — what is certified as already solved, what we build, and what we
explicitly refuse.

The through-line of every accepted item is one sentence: **the framework's
agent-native property is that its runtime is deterministic, its failures
are loud and machine-addressable, and its contracts have exactly one
declaration site.**

## 1. Certified: classes nisli already eliminates

The audit's first output is a defense list — industry bug classes that are
*unrepresentable* in nisli today. These become documented invariants (docs
+ the 0030.1 B3 gotchas tier lead with them; tests already pin most):

| Class (industry evidence) | Why it cannot happen here |
|---|---|
| Dependency arrays / stale closures ([React YMNNAE](https://react.dev/learn/you-might-not-need-an-effect)) | Automatic tracking; signals read current values |
| Manual batching decisions | Deleted (ADR 0015) — coalescing is automatic |
| Computed diamond glitches | Pull-based lazy computeds (verified in tests) |
| Stale async overwrites | `resource()` abort + generation discipline (0028) |
| Synthetic-event surprises | Native `addEventListener`, typed via `TypedEventHandler` |
| Lit-style directive taxonomy misuse (guard/cache/live/repeat) | Signals + `each()` subsume it; no directive layer exists |
| `class` attribute vs `classList` conflicts | Owned-classlist diffing (ADR 0007) |
| Duplicate-key list corruption ([react#29116](https://github.com/facebook/react/issues/29116)) | `each()` validates the key set first; skip-and-preserve with recovery — better than React's corruption *and* better than hard-throwing |
| Pre-upgrade property shadowing ([the classic WC bug](https://nolanlawson.com/2021/08/03/handling-properties-in-custom-element-upgrades/)) | No property accessors exist; factory `createElement` upgrades synchronously |
| Shadow-DOM SSR/FOUC and slot folklore ([WICG #737](https://github.com/WICG/webcomponents/issues/737)) | Light DOM + SSG real HTML; `children()` one-reactive-slot + late-parser sweep |
| Reflection loops ([lit-element#965](https://github.com/lit/lit-element/issues/965)) | Reflection is explicit with a pin discriminator, single ownership |
| Form-associated custom element machinery | Real native inputs (0019/0022) — no `ElementInternals` needed |
| Context default-value shadowing / silent `undefined` inject | No default-value concept; throw into the boundary with `providerTag` naming |
| Hierarchical-DI complexity (Angular's NullInjectorError taxonomy) | Two *flat* systems: app-singleton `inject`, subtree `createContext` |
| Move/reorder disconnect races — including foreign movers | Deferred teardown (0023) |
| Tag collisions needing scoped registries | Platform's scoped registries are shadow-root-only — useless for light DOM; **copy-in one-version-per-tree is the collision architecture**, stated as such |

## 2. Decisions — Tier 1 (flagship sidesteps; each graduates via a 0025-style design gate)

### T1. Query becomes a keyed logical-request store

The five open query issues (0005–0009, four of them P0) are **one
architectural mistake**: per-call-site closure state over a dumb cache
`Map`, with the dedup unit being a fetch *attempt* (`query.ts:96–107`)
instead of a logical request. The sidestep is `resource()`'s architecture
applied to the shared cache: a per-key record in `QueryClient` —
`{data, error, status, fetchedAt}` as signals plus one `run()` owning the
retry loop, an `AbortController` passed to the fetcher, and cache commit —
with `query()` reduced to a thin observer whose outputs are `computed()`
over the record its current key points at.

Then, **by construction**: dedup unit = logical request (0005); invalidate
marks stale and reruns records with observers (0006); on disable/key-switch
the observer just points elsewhere — stale `loading` is unrepresentable
(0007); the runner starts via `Promise.resolve().then(...)` so sync throws
are rejections (0008). The key contract goes **flat**:
`readonly (string|number|boolean|null)[]` — objects are *rejected* with a
coded dev error rather than canonicalized, deleting both serialization
algorithms and the whole collision/ordering class (0009). `onSuccess`/
`onError` are dropped (TanStack removed them in v5 for the same state-sync
reasons); the silent local-`QueryClient` fallback becomes loud.

`query()` has **zero production consumers** (www docs only), so the
breaking cost is ~nil and the size is likely net-negative. Five open issues
close as a class.

### T2. `settle()` — awaitable async quiescence

T1's store gives a registry of pending logical requests for free; adding
`resource()` generations yields `await settle()`: loop
`Promise.allSettled(pending)` then `tick()` until both are empty. Agents
(and tests) get `await settle(); expect(...)` — deterministic, no
`waitFor` polling. **No query library ships this** (TanStack's own testing
guidance is "poll `isFetching`"; the only prior art is Ember's
`settled()`). Honest bound documented: framework-started promises, not
fetcher-internal timers — `tick()`'s existing contract. This is the verify
loop's (0030.1 B4) determinism primitive.

### T3. Schema-as-single-truth component declarations

Today a component's contract is declared three times — the `P` type, the
`attrs` const, and the `typeof` type argument — because TypeScript lacks
partial inference (the "inference wall", 0025 §3), and template/factory
prop names are runtime-unchecked (the props proxy mints a signal for any
key). Invert the direction: declare the schema once as **values**, infer
everything from it:

```ts
const Switch = component('ui-switch', {
  checked: p.boolean(),
  name: p.forward(),
  onChange: p.event<boolean>(),
}, (props, host) => { ... });
```

Prop types infer from the schema; attributes auto-derive for every
stringable kind; the dev props proxy seals unknown keys. This eliminates
the inference wall, the entire `AttrValueType`/`IsExactKind` soundness
apparatus (declaration and type are one object — mismatch is
unrepresentable), and props-vs-attrs drift as a class. The agent payoff:
**manifest-grade metadata without a compiler** — import the module, read
the schema, emit the manifest — which is the ground truth 0030.1's A4
lint, B1 warnings, and B5 MCP tools were otherwise going to approximate.
Add `p.state()` for owned-but-controllable state: core owns the
attr↔signal sync, pin-as-controlled-discriminator, and default seeding
that every overlay root currently copies as ~8 lines of choreography
(0025 §3 open-state pattern), deleting it registry-wide.

Breaking but mechanical: the `component<P>(tag, setup, opts)` form stays
as an overload; the house has done 36-file migration waves before.

### T4. Parse-once templates + the first-parse audit

`template.ts` re-parses on every mount — the declared `templateCache`
(`template.ts:46`) is never read (open issue 0015). Fix that (parse once
per callsite), then attach a **one-time static audit at that parse**: walk
the parsed template and check dash-tags against the live `customElements`
registry (microtask-deferred for lazy definition), attributes against the
target's schema/`observedAttributes`, `@event` names against native events,
unknown modifiers, malformed binding positions — each a coded dev
diagnostic naming the callsite. The silent-static-typo class — the
no-build equivalent of a compile error — dies **in the engine**, amortized
free, no compiler. (0030.1's A4 static lint remains as the editor/CI twin;
this is the runtime truth it approximates.) Also on this foundation:
`mount()` of an already-mounted, un-disposed `TemplateResult` throws
(shared-binding corruption, 3 lines).

### T5. The deterministic, self-diagnosing scheduler

Three source-level findings, one upgrade:

- **Finish the house's own algorithm**: `NodeState.MaybeDirty`
  (`signal.ts:91`) is declared but never assigned — the push-pull design is
  half-implemented, so effects re-run when intermediate computeds
  recompute to *equal* values. Completing it (~40 lines) establishes the
  machine-checkable invariant: **an effect re-runs iff a value it read
  changed.**
- **Deterministic order**: effect re-tracking currently reshuffles
  observer sets, making flush order history-dependent. A monotonic
  creation index + sort on flush (~15 lines) makes identical writes
  produce identical run order, forever — reproducible traces.
- **Sited, deterministic loop diagnostics**: the loop guard counts
  wall-clock `Date.now` (nondeterministic under CI/fake timers) and names
  no effect. Diagnose write-inside-own-tracking-effect **at the write**
  (the stack names the offending line), count logical flush generations
  instead of wall time, carry dev-captured effect identity, and make the
  silent `flush()`/`tick()` cap breaks loud — the exact ask filed against
  Svelte ([#13950](https://github.com/sveltejs/svelte/issues/13950)),
  sidestepped. Write-during-computed-compute becomes a coded purity error
  (today it silently self-stales).

### T6. Failure is a DOM fact

Setup, `onMount`, and effect failures have **three different containment
semantics** today (full boundary vs console-and-limp vs console-and-live).
Unify: an `onMount` throw routes through the same boundary as setup; every
contained failure **stamps the host** — `data-nisli-error="N4xx"` plus a
bubbling `nisli-error` event `{code, tag, phase, message}`. "Which
component failed" becomes `querySelectorAll('[data-nisli-error]')` —
deterministic machine output readable by verify (B4), Playwright, and any
agent loop, in the DOM where agents already look. `_remount()` is
documented as the boundary reset (Solid-parity recovery). ~150 bytes.

## 3. Decisions — Tier 2 (small, loud-by-design, platform-aligned)

- **`effect(async …)` unrepresentable** — runtime coded diagnostic naming
  `resource()` + rejection routing + a type overload rejecting
  Promise-returning functions. Three silent failure shapes die in ~10
  lines; zero existing sites (verified by grep).
- **`when()` boolean-gated, with `else`** — gate on `!!cond` and evaluate
  branches untracked: truthy→truthy and tracked-read-inside-branch
  rebuilds (state/scroll/focus loss) become impossible; the `else` arm
  closes the `&& 0` escape hatch by making `when` complete.
- **Loud duplicate `define`** — registration is first-wins-*silently*
  today (`component.ts:627–629`): the wrong component renders while the
  factory typechecks against the wrong props. Prefer making bare
  redefinition *work* (swap setup + `_remount` — the HMR path generalized);
  else a coded error naming both definition sites.
- **Factory-in-tag-position** — `` html`<${Dialog} open>…` `` : a
  misspelled component identifier becomes a TypeScript error instead of
  inert DOM. Plus the dev-only painter: still-undefined dash-tags get a
  labeled red box — **visible in screenshots and aria snapshots**, strictly
  stronger than a console warning for agent verification loops.
- **Unknown-prop echo** — after setup, `_setProp` on a key the setup never
  read is a coded diagnostic (catches `varian=` through factory *and*
  template auto-resolution paths).
- **`html:inner` takes branded trust only** — `raw()` (unified with
  `@nisli/ssg`'s existing brand) or `TrustedHTML`; bare strings throw.
  Zero registry consumers today — the accidental-XSS-sink class closes at
  ~nil cost; Trusted Types is Baseline and the Sanitizer API is shipping.
- **Phase-ordered projection sweep** — move the late-children sweep
  scheduling out of `children()`'s own `onMount` into a dedicated
  pre-`onMount` phase in `component.ts`; the documented
  `children()`-before-`onMount` ordering trap (0025 batch-3B gap a) stops
  existing.
- **`moveBefore()` adoption** — define an empty `connectedMoveCallback` on
  the base class (moves by *any* actor become spec-level no-ops) and use
  `moveBefore` in `each()`/portal when available: preserves the platform
  state (focus, animations, iframes) that deferred teardown cannot.
  Feature-detected, ~10 lines, completes ADR 0023 on the platform's terms.
- **DI freeze-after-first-inject** — `provide()` on an already-
  instantiated token is a coded dev error ("resetInjector() first");
  today it silently splits the app into mixed-instance brains
  (`injector.ts:113–120`).
- **Pre-upgrade transparency** — SSG serializes `style="display:contents"`
  on component hosts (or theme.css enumerates registry tags, generatable
  from T3's manifest): the pre-upgrade layout-shift class on static pages
  ends.
- **Papercuts folded into the nearest batch** — `untrack<T>` returns its
  value; `signal.peek()`.

## 4. Explicitly not taken

- **Dev freeze-on-write** (mutate-then-no-render loudness): real risk that
  frozen objects escape the reactivity scope; parked until the A5 drift
  corpus shows mutation is a top observed agent error. Revisit as
  opt-in-shallow.
- **Occurrence-composite `each` keys**: would make duplicates well-defined
  — and mask data bugs. Current validate-first, skip-and-preserve semantics
  are best-in-industry; codified instead.
- **`linkedSignal` / derived-state primitive**: below the second-consumer
  bar (registry grep shows write-in-effect sites are DOM writes); becomes
  an A5 drift-lint rule instead.
- **Named/multiple projection slots; HMR local-state carry**: single
  recorded consumer each (WWW-12; industry-accepted resets) — the
  second-consumer discipline holds.
- **Deep reactivity / proxies**: stays rejected (0019).
- **Upgrade-order-safe `inject` deferral** (defer setup on
  `whenDefined(providerTag)`): correct shape, no in-repo consumer yet —
  **gated on the 0025 §17 hydration/islands disposition**, where the race
  goes live.

## 5. Interaction with the hydration question (0025 §17)

The one big open architectural item on the books — Goga's
adopt-in-place-instead-of-replace question — is not decided here, but
three accepted items are its enablers and are sequenced with it in mind:
T4's parse-once cache makes per-callsite binding positions stable (the
claim map any `adopt()` needs); T3's schema makes attribute state the
single truth an adopted DOM can be read back from; and the `moveBefore` +
deferred-setup items remove the upgrade-order and platform-state hazards
islands would surface. Disposition still follows WWW-15 evidence, per the
tracker.

## 6. Sequencing and budget

Design-gate discipline (0025 process) — each Tier-1 item lands as
prototype → design gate → migration, one at a time:

1. **Wave 1 — no API change, pure wins**: T4 parse-once + audit; T5
   scheduler determinism; T6 failure-DOM-fact; projection phase;
   `effect(async)` guard; single-mount throw; DI freeze; duplicate-define
   loudness. (Populates the 0030.1 B2 code registry with its first real
   taxonomy: N1xx template, N3xx reactivity, N4xx lifecycle.)
2. **Wave 2 — zero-consumer rewrite**: T1 query store + flat keys + T2
   `settle()`.
3. **Wave 3 — breaking-mechanical migration wave**: T3 schema + `p.state`
   (+ manifest emission), factory-in-tag-position, `html:inner` branding,
   pre-upgrade transparency.
4. **Gated**: upgrade-order-safe inject with 0025 §17.

Budget: Tier 1+2 sum to roughly +2KB before the query rewrite's
net-negative offset; adopt a CI-enforced ceiling — `@nisli/core` stays
under **10KB min+gzip** (8.8KB today) — so the loudness investments are
paid for by deletions, in the 0015 tradition.

## 7. Placement, layering, and API-surface accounting

The decisions above must land inside the repo's existing structure, not
beside it. Verified from source (`packages/core/package.json` exports map;
import graph; `src/index.ts`):

**Module layering.** The dependency direction is
`signal.ts → template.ts → component.ts` (component imports signal,
template, context, lifecycle, ref). New work respects it:

- T5 lives entirely in `signal.ts` (+ tests). Diagnostic **codes** come
  from a new leaf `diagnostics.ts` importable by every layer without
  cycles — codes and a minimal payload builder only, no docs prose.
- T4's cache lives in `template.ts`; the audit walker is a sibling
  `template-audit.ts` imported only under the dev flag, so the engine file
  keeps its current size discipline.
- T6 lands in `component.ts`/`lifecycle.ts`, where the boundary already
  lives. T1 rewrites `query.ts` in place; `settle()` is a top-layer leaf
  (`settle.ts`) importing signal + query + resource.

**Dev-only weight follows the vite-hmr precedent.** The exports map
already models it: `.` (prod), `./vite-hmr`, `./vite-hmr/runtime`.
Everything with real dev weight ships the same way: the first-parse audit
behind the build-time define; the introspection global as a
`@nisli/core/devtools` subpath entry (zero bytes in `.`); rich diagnostic
payloads dev-gated. The 10KB budget (§6) is measured on the `.` entry and
is unaffected by dev entries.

**API-surface tally** — 0030 §1 makes the small barrel a governed budget,
so the additions are counted, not implied. `src/index.ts` holds **12
export statements** today. Tier 1+2 adds: `settle()` (+1), the `p` schema
namespace (+1 — one namespace object, not per-kind exports), `raw()` (+1
worst case; the gate should first try unifying with `@nisli/ssg`'s
existing brand). Everything else costs zero statements: `when()`'s else
arm is an argument; the effect(async) guard, duplicate-define loudness,
DI freeze, `moveBefore` adoption, and single-mount throw are semantics of
existing exports; `__NISLI__` is a global on the devtools entry;
`data-nisli-error`/`nisli-error` are DOM contract, documented not
exported. **Ceiling: the source barrel stays ≤ 15 export statements after
all Tier 1+2 work**, checked in CI alongside the llms-core token budget
(0030 §5) — the same conscience, enforced twice.

**New packages.** `@nisli/verify` (0030.1 B4) is the only new workspace
package this program creates. `packages/*` is globbed by the workspace and
the push-triggered auto-tag release flow — its first publish must be
deliberate and sequenced with arch, not a side effect of landing source.

**Registry placement.** New lib items obey 0022's frozen
`ui/ lib/ styles/` layout: `lib/parse-ui.ts`, `lib/app-bridge.ts`,
`lib/model-context.ts` (0029/0030.1). No new top-level registry
directories, so copies keep surviving verbatim.

**Test placement.** Co-located `*.test.ts`; type-level proofs in
`*.test-d.ts` (T3 extends `component.test-d.ts`'s precedent);
cross-cutting invariant pins join `invariants.test.ts` — T5's invariant
("an effect re-runs iff a value it read changed") is pinned there once,
instead of scattered run-count assertions.

**Pattern conformance.** T3's schema slots into the existing
**SEED → CAPTURE → CONTEXT → setup** order (SEED reads the schema where it
reads `attrs{}` today; the other phases are untouched); `p.state`
implements the 0025 open-state ruling verbatim (seed-once, pinned-skip,
explicit-`"false"`-beats-default, reflect effect) as core behavior; the
projection-phase move relocates *scheduling* only — the read-and-render
correction (children() reads the prop signal, never relocates nodes)
stays intact.

## Consequences

**Positive.** The framework-level meaning of "agent-native" stops being
abstract: deterministic scheduler, loud machine-addressable failures,
single-declaration contracts, and a template engine that validates its own
static parts. Five open P0/P1 issues close as one class (T1); issue 0015
closes as a side effect of T4; three 0025 residuals (open-state
choreography, inference wall, children/onMount ordering) dissolve rather
than get documented harder. Every 0030.1 instrumentation item gains a
foundation it lacked (manifest ← T3; A4's runtime half ← T4; B4's
determinism ← T2/T5; B2's first taxonomy ← Wave 1).

**Risks, owned.** T3 is a real migration wave across 58 registry items —
mechanical, but it lands once, behind a design gate, with the legacy
overload keeping old code compiling. T5 changes observable run counts and
order — that is the point, but suites pinned to incidental behavior will
need updating (the invariant they should pin is the new one). Wave 1's
diagnostics are dev-only weight; the prod path stays untouched. Twenty-two
of twenty-eight proposals were accepted only as smalls or refused —
the curation *is* the deliverable; scope discipline holds via the
one-gate-at-a-time rule.
