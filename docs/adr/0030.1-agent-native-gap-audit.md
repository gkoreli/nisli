# 0030.1. Agent-Native Authoring — Gap Audit and Work Plan

**Date**: 2026-08-09
**Status**: Proposed
**Depends on**: [0030-agent-native-authoring](./0030-agent-native-authoring.md)

## Context

ADR 0030 names the thesis. Review put two fair challenges to it:

1. *"Nisli already kinda does all of this — so what?"*
2. *"Devtools are one part of the story; the bigger part is building. Is this
   already the best agent-native UI framework? If not, why not, and what
   would make it better?"*

This ADR answers both with an audit against evidence: four research passes
(August 2026, primary sources read, not summarized) over the frameworks and
languages designed or retrofitted for LLM authorship (MoonBit, FastHTML and
the llms.txt lineage, HTMX, Svelte's drift response, Angular, Nuxt); the
system prompts and engineering writeups of every platform that generates UI
at scale (v0, Lovable, Bolt, Replit Agent, Claude Artifacts, ChatGPT Canvas,
Val Town's Townie, GitHub Spark, Thesys); the diagnostics, introspection,
and verification machinery agents actually consume (rustc, TypeScript,
Biome, Playwright ariaSnapshot and Playwright MCP, Chrome DevTools MCP,
solid-devtools, Lighthouse); and eval methodology (Aider, the SWE-bench
failures, Web-Bench). Key sources are linked inline; the leaked prompt files
are archived for exact-line citation.

**The verdict, stated plainly.** Nisli already has the *substrate* the
ecosystem's revealed preferences converge on — and almost none of the
*instrumentation and packaging* that the same evidence says carries the
weight. In practice, the best agent-native UI stack today is still
React + Tailwind + shadcn: not because of design, but because of training
corpus, scaffold gravity, and the repair/feedback pipelines platforms built
around it ([Vercel reports frontier models err ~10% on web code and answers
with autofixers, not prompts](https://vercel.com/blog/how-we-made-v0-an-effective-coding-agent)).
Every advantage that stack holds over nisli **except corpus presence** is
closable work. This ADR is that work, ordered.

One calibration the evidence forces on the thesis: with zero training-data
presence, *"written by agents"* is not claimable by design —
[Web-Bench](https://arxiv.org/html/2505.07473v1) measured framework success
tracking corpus mass (React 65% vs Svelte 25% for the same model), and
MoonBit, maximally AI-native by design, stayed niche and pivoted to
tooling. What design claims structurally is *"verified and debugged by
agents"*; *written by* is *earned* at inference time — docs-in-context plus
the loop (Svelte's playbook: tiered llms.txt **and** an
[autofixer named after observed model mistakes](https://github.com/sveltejs/mcp),
because docs alone did not stop the drift).

## 1. What already holds — the substrate is the revealed ideal

The constraints every generation platform enforces by prompt are the
profile nisli has by architecture:

| Convergent constraint (evidence) | nisli today |
|---|---|
| Self-contained, fully-regenerable unit — v0 2024: "ONLY SUPPORTS ONE FILE"; Bolt: files "as small as possible"; one val = one file | ✓ one-file components; copy-in registry |
| Closed, pinned import surface — Artifacts pins `lucide-react@0.383.0`; Vercel built embedding autocorrect for hallucinated imports | ✓ zero-dep registry, imports only `@nisli/core`, CI-enforced (UI-37) |
| Tokens, never raw values — v0 and Lovable use near-identical wording | ✓ shadcn token layer verbatim |
| Full-content rewrites over diffs — [Val Town measured diffs and turned them off](https://blog.val.town/fast-follow) | ✓ small, wholly-rewritable files |
| Instant deterministic boot — WebContainer, Spark's managed template, artifact iframes | ✓ no build step; SSG; Vite optional |
| Whole competence fits in a prompt — [Townie's winning prompt was "an abbreviated quickstart"](https://blog.val.town/codegen) | ✓ 14 export statements — but unpublished (→ B3) |
| Behavior local to the unit — [HTMX Locality of Behaviour](https://htmx.org/essays/locality-of-behaviour/); MoonBit's anti-nesting | ✓ light-DOM templates in the component file |
| Layered mechanical feedback, cheapest first — all platforms | ✗ exists only as in-repo harness (→ B1, B4) |
| Dominant-dialect familiarity | ✗ structural; routed around, never closed (→ A5, B3) |
| Generate-data-not-code option — [Thesys](https://www.thesys.dev/blogs/generating-code-for-generative-ui-is-a-bad-idea), remote-dom | ✓ attribute-complete components; `parseUi` decided in 0030 §4 |

Seven of ten by construction. The audit below is the other three, split into
the two tracks review asked for — and the **authoring track comes first
because it is the bigger half**.

## 2. Track A — the authoring substrate (the "building" half)

### A1. `npm create nisli` — the known-good starting point

**Gap.** Every platform that generates UI reliably starts agents inside a
pinned, working environment (Spark: "opinionated stack for reliability";
v0's managed scaffold; the 20.8k-star ai-chatbot template as React's
gravity well). Nisli has no scaffold; an agent starting cold must assemble
Vite + Tailwind v4 + theme.css + registry init by hand — the highest-risk
phase of the whole loop, before any feedback exists.

**Deliverable.** A create-command that lands the full known-good
environment in one step: Vite + Tailwind v4 + theme + initialized registry
+ the app shape of A2 + a curated `AGENTS.md` (pointing at the B3 context
artifacts and naming the verify command) + `nisli verify` preconfigured.

**Acceptance.** Cold directory → themed rendered page with verify green in
under a minute, zero manual steps; the scaffold's `AGENTS.md` passes the
[curation test](https://arxiv.org/abs/2602.11988) (hand-written, no
generated boilerplate — developer-written context measured +4%, generated
−3%).

### A2. The app shape — one deterministic structure

**Gap.** Agents build apps, not components, and where conventions are
absent every agent invents structure — the drift compounds across sessions.
React apps inherit Next's conventions from the corpus; nisli has router,
query, DI, and SSG but no named shape for how an application composes them.
[Modem.dev's evidence](https://modem.dev/blog/how-coding-agents-read-your-code)
is direct: concept-named modules cut agent token spend 31–34% and doubled
bug detection; grep-unique 2–3-word exported names are how agents navigate.

**Deliverable.** "The nisli app shape": a short normative doc — file
layout, route catalog placement, where services/state live, naming rules
(component = tag = file = export, grep-unique) — implemented by the A1
scaffold and dogfooded by `packages/www` as the reference.

**Acceptance.** The shape doc fits in the B3 small-tier context budget; www
conforms; the fleet's own worklists cite it.

### A3. HTML-first authoring as the documented primary dialect

**Gap.** The strongest corpus any model has is plain HTML — and nisli is
the rare framework whose components are attribute-complete custom elements
(0022 tenet 2), so most UI is expressible as declarative markup with
factories only for wiring. Today the docs lead with the TypeScript factory
dialect; the dialect agents are natively fluent in is treated as the
fallback.

**Deliverable.** Invert the documentation default: markup-first examples
everywhere both dialects work; the factory path presented as the
enhancement for logic. This is positioning work, not code — the substrate
already permits it.

**Acceptance.** Every registry item's docs open with the plain-HTML form;
B3's small tier teaches markup-first.

### A4. Template static analysis — the missing markup typecheck

**Gap.** No-build removes the cheapest feedback layer every platform
harvests (build errors), and custom elements fail *silently*: a misspelled
`<ui-dialgo>` or an undeclared attribute renders as inert nothing — the
["Potemkin interface" failure Replit built browser-testing infrastructure
to catch](https://replit.com/blog/automated-self-testing), and nisli's
equivalent of the hallucinated-import class that
[Thesys found to be the top compile failure](https://www.thesys.dev/blogs/generating-code-for-generative-ui-is-a-bad-idea).
JSX projects get this from the type checker; tagged templates do not check
their static parts.

**Deliverable.** A static lint over templates and plain HTML: every
`ui-*`-prefixed tag must resolve to a registered component, every attribute
/ event / `data-slot` must exist in the manifest (0029 §4), with
machine-applicable fix suggestions where unambiguous (rustc's
`suggested_replacement` + applicability model). Runs standalone and as
verify's static level.

**Acceptance.** Misspelled tag, attribute, event, or slot in the fixture
app → one coded diagnostic with a fix; zero false positives across the
58-item registry corpus.

### A5. The drift linter — observed mistakes become rules

**Gap.** Svelte proved docs alone don't stop dominant-dialect drift; their
MCP server's autofixer directory is literally
[a file per observed LLM mistake](https://github.com/sveltejs/mcp)
(`use-runes-instead-of-store.ts`, `assign-in-effect.ts`). Agents will write
React into nisli files: JSX prop syntax, `useEffect`-shaped effects,
synthetic-event assumptions, `className`.

**Deliverable.** A lint pack whose rules are named after mistakes actually
observed in the fleet's review history (the standing corpus 0030 §6 makes
of it), each carrying the nisli translation as its fix; plus a
"coming from React / Svelte / Vue" translation table opening the B3 small
tier (`className` → `class`, `onClick` → `@click=${…}`, `useState` →
`signal`, `useEffect` → `effect`).

**Acceptance.** v1 ships ~10 rules, every rule's docs citing the real
observed error it encodes; wired into A4's lint and B5's tools.

## 3. Track B — the loop instrumentation (the "devtools" half)

### B1. Make silence loud

Dev-mode runtime warnings completing A4 at runtime: unregistered
`ui-*`-prefixed tag still undefined after the upgrade window; undeclared
attribute on a nisli component; both as coded diagnostics (B2). This is the
build-error *substitute* — the cheapest mechanical signal restored to a
no-build framework.

### B2. The diagnostics registry

Adopt, exactly: TypeScript's append-only never-reused codes; Biome's
category path doubling as the docs slug (`reactivity/write-in-effect` →
`nisli.dev/errors/…`); rustc's spans + `suggested_replacement` +
applicability tiers; cargo's NDJSON envelope with a terminal
`{reason:"done", success}`; React's decoder-URL pattern for production.
One registry file generates docs pages and runtime lookup; CI fails a
code-less throw site and a code without a docs page. (Refines 0030 §3 with
the concrete lineage.)

### B3. Context artifacts — tiered, gotchas-first, budgeted

The evidence recalibrates *why*: [llms.txt as a crawler signal is dead
(0% of monitored fetches came from AI bots over seven months)](https://www.digitalapplied.com/blog/llms-txt-in-practice-adoption-evidence-2026)
— its live value is coding agents fetching **at inference time**. Ship:
`llms.txt` index + small/medium/full tiers (Svelte's sizing), `.md` twins
per docs page, a generated `apilist.txt` of all export signatures
(FastHTML's pattern), and — first thing in the small tier —
[FastHTML-style "things to remember"](https://www.fastht.ml/docs/llms.txt):
the ~10 corrections of the most likely wrong priors, including A5's
translation table. Budgets CI-enforced (small ≤ 4k tokens, full core
reference ≤ 8k per 0030 §5), generated from the same sources as the human
docs.

### B4. The verify verdict contract

The www sweep is ~70% of the harness; the product is the contract. Adopt:
Lighthouse's audit result object (`id`, `score`, `scoreDisplayMode`
binary/numeric/informative) as the per-check verdict; Playwright's
separation of observation from expectation (`expected` / `unexpected` /
`flaky` + stats rollup); ariaSnapshot YAML as the semantics fixture format
(it is what agents already read through Playwright MCP); axe-core and
console-error-free as standing checks; audit ids reuse B2 codes where one
diagnostic explains the failure. Previews are the fixtures (Storybook's
lesson). No LLM judge anywhere in the gate —
[FrontendBench hit 90.5% human agreement with deterministic assertions
alone](https://arxiv.org/html/2506.13832v1). (Refines 0030 §2.)

### B5. `@nisli/mcp` — docs as tools

[Svelte's four tools](https://svelte.dev/docs/ai/llms.txt) are the
template: `list-sections`, `get-documentation`, the autofixer (A4+A5 as a
tool), and a preview link (www); plus registry search/install (the
[shadcn MCP precedent](https://ui.shadcn.com/docs/registry/mcp), shared
surface with 0029 §4). An in-dev-server variant
([nuxt-mcp](https://github.com/antfu/nuxt-mcp)'s live-app introspection) is
a later option.

### B6. The introspection graph — kept, honestly last

The evidence demotes it: React and Vue devtools protocols existed for years
with effectively zero agent uptake; agents thrive on generic surfaces
(accessibility tree + console + `evaluate_script`), and
[Playwright MCP's own docs warn against verbose trees in context](https://github.com/microsoft/playwright-mcp).
So: scoped queries only — `deps(el)`, `whatChanged(el)` — never a full
graph dump; solid-devtools'
[`SerializedDGraph`](https://github.com/thetarnav/solid-devtools) as the
internal shape; lazily-deepened value encoding; judged by
tokens-per-answered-question; consumable through `evaluate_script` in the
MCP servers agents already run, so it needs no new tooling to be used.
Protocol marked unstable until proven. (Refines 0030 §3; supersedes its
implied priority.)

## 4. What we deliberately do not take from the prior art

- **No fine-tuned repair models, no embedding services** (Vercel's
  `vercel-autofixer-01` path) — nisli is not a hosted platform;
  deterministic lint and diagnostics only.
- **No single-file-app dogma** — platforms abandoned strict one-file the
  moment they had filesystems; the durable form is *small regenerable
  units*, which nisli already is.
- **No LLM-as-judge in the verify gate** — deterministic checks gate;
  judges, if ever, annotate.
- **The eval stays deferred** (0030 §Deferred), now with sharper evidence:
  OpenAI [stopped reporting SWE-bench Verified after 59.4% of audited
  failures proved test flaws](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/),
  and the methodology review's verdict on a self-published benchmark
  without pre-registration, outside task authorship, and a third-party
  rerun is that it is *marketing with confidence intervals*. When
  revisited, the shape is [SvelteBench](https://github.com/khromov/svelte-bench)'s:
  pass@k with and without docs-in-context, the with-docs condition as the
  headline — which also measures exactly what B3 exists to provide.

## 5. Invariants to codify (additions to 0022/0030)

- Component = tag = file = export name, grep-unique.
- No companion files: one read is the whole truth.
- Registry items stay fully-rewritable (size soft-budget, checked in
  review, not CI).
- Every dev-mode failure is loud, coded, and carries its fix hint; silence
  is a bug class (B1).
- Diagnostic codes are append-only, forever, or the registry is worthless.
- Docs examples are complete runnable files, never fragments.

## 6. Sequencing — supersedes 0030 §Sequencing

Priority order, with the reasoning that produced it:

1. **B1 + B2** — restore the cheapest feedback signal; everything else
   attaches diagnostics to it. Smallest work, largest reliability delta.
2. **B3** — with zero corpus presence, context artifacts carry 100% of the
   "written by agents" weight; nothing else matters if the agent's priors
   are wrong.
3. **A1 + A2** — the scaffold and the shape: the adoption front door and
   the determinism agents build inside.
4. **A4** — the markup typecheck; needs the manifest (0029 §4), pays the
   biggest single correctness dividend after B1.
5. **B4** — the verdict contract over the existing harness.
6. **A5** — continuous; feeds on the fleet corpus as it accumulates.
7. **B5** — packaging of B3 + A4 + A5 as tools.
8. **B6** — last, by the uptake evidence; scoped queries when it comes.

Worklist grouping (AGN-* tickets) is the architect's call; the order above
is the decision.

## Consequences

The thesis becomes checkable work: eight items, each small enough to land
independently, each carrying its evidence. Track A outweighs Track B —
review was right that building is the bigger story, and five of the eight
top slots are authoring-substrate work. The risks are inherited from 0030
(instrumentation maintenance, append-only discipline) plus one new one:
A1–A3 are opinion-heavy surfaces (scaffold defaults, app shape, doc
inversion) — cheap to build, expensive to churn; they should land once,
reviewed against this ADR, not iterated in public.
