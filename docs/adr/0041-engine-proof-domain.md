## Context

The north star ([`NORTH-STAR.md`](../research/nextgen/NORTH-STAR.md)) makes
two promises in one breath: *correct in every context*, and *verified without
looking*. 0034 delivered the first half — fifteen blocks whose decisions are
data — and named a Proof context for the second, with one sentence: "a screen
mounted at widths with no browser, returning its layout reports". Issue 0024
parked it the next day: no Ledger screen called `prove()`, the estimator had
never been compared to Chromium, and correctness at width was still a
Playwright sweep and a person looking. The second promise was true only for a
human with a browser.

An inventory of the Proof context at `main @ 0a6dfed` (no code changed) found
the gap was wider than "unused":

- `prove()` checked one thing — a `LayoutReport` filed via `reportIf` — and
  only three blocks file one (`FIT_ROW` from Toolbar, `FIT_COLUMNS` from
  Table, `FIT_CELL` from Grid and Form). Page, Section, Stat, Bars, Columns,
  Meter, Dialog, Notice, Empty, Text and App could not fail a proof.
- The estimator sized text at a flat `7.2 px` per character; block tests
  used `textMeasurer(8)` because `8 + 24 = 32` made the `⋯` trigger's
  arithmetic convenient; real Chromium `system-ui` at 14 px averages
  6.9–7.4 by glyph mix. Three numbers, never reconciled. Font weight,
  heading size, `letter-spacing`, `text-transform` and `tabular-nums` were
  ignored.
- Boxes ignored borders, margins, scrollbars, `minmax`/`auto` tracks, flex
  shrink and a table's cells (columns were measured from `thead th` only, so
  a long payee was invisible).
- A `report()` with no listener only `console.error`ed — a dev signal, not a
  test signal — and a happy-dom proof had no way to tell whether a report was
  still standing once the screen settled.
- The scratchpad Playwright checks (horizontal scroll, console errors, block
  errors, hidden headers, menu and dialog keyboard sequences, focus return)
  lived in throwaway scripts that no review had passed
  ([harness attestation](../../.agents/skills/nisli-engine/SKILL.md)).

The panel of 2026-08-30 chose to re-found the Proof context now, because the
block vocabulary had held for a week of Ledger use (0024's first un-parking
condition) and because every later round — the vocabulary contract,
reachability, density — needs a proof to land against.

## Ubiquitous language

| term | meaning | where it lives |
|---|---|---|
| **Report** | The engine saying, in data, that a plan could not be satisfied: `LayoutReport { code, block, detail, deficit, width }`. Filed by `reportIf` from inside a block's decision. | `engine/report.ts` |
| **Evidence** | What the runtime leaves behind so a report can be read later without a listener: `data-nisli-report="CODE"` on the block's host while unsatisfied, and the `window.__nisli.reports` ring. Dev-only. | `engine/report.ts`, `engine/dev.ts` |
| **Claim** | Something a proven screen must hold, stated as data: `Claim { code, block, detail, severity, width? }`. A report still standing is one claim among eleven; the others are things a person would otherwise catch by eye or keyboard. | `test/claims.ts` |
| **Checker** | A pure function over the mounted tree plus the estimator that returns the claims it can make: `{ code, check(root, measure) }`. Every checker has a positive and a negative fixture test. | `test/claims.ts`, `claims.test.ts` |
| **Estimator** | A `Measurer` for happy-dom: box widths from the engine's own inline styles walking down from a frame width; text widths from summed per-glyph advances at the inline `font-*` the skin wrote. | `test/estimate.ts` |
| **Calibration** | The measured table the estimator sums from — per-glyph advances and reference string widths for the default skin's font stack at every text style — generated from real Chromium, held within a stated tolerance by a test. | `scripts/calibrate-glyphs.mjs` → `test/glyphs.ts`, `glyphs.test.ts` |
| **Proof** | `prove(make, { widths, viewport?, scheme?, turns? })`: a screen mounted at each width under the estimator, run to a fixed point, with every checker applied. `Proof { claims, reports, byWidth }`; an empty `claims` is the proof. | `test/prove.ts` |
| **Verify** | The browser half: `verify({ baseUrl, routes, widths, … })` loads a running app in Chromium and reads the evidence plus what only a browser can see. Returns `Finding`s, not claims — a finding is at a route, a claim is on a block. | `verify/index.ts`, `bin/nisli-verify.mjs` |

**Proof observes Decision and never influences it.** Nothing in `test/*` or
`verify/*` is imported by a block; the only runtime code this ADR adds to
the engine is the evidence stamp, which writes to the host element and a
ring, is compiled out in production, and is read by no decision. The
dependency direction of 0034 stands: Intent → Decision → Appearance, with
Proof reading Decision through `onReport` and the DOM.

## The estimator and its calibration

The old estimator was a guess. The new one is a sum over a measured table.

**Method.** `pnpm calibrate` (`scripts/calibrate-glyphs.mjs`, Playwright
resolved from `packages/www`) opens Chromium, lays out every glyph the engine
puts on screen in a span carrying the default skin's font stack, and records
its advance at each text style the skin writes inline: 14/400 body, 14/500
control, 12/400 small, 12/500 header, 16/600 title, 20/600 heading, 28/600
display, and 14/400 monospace for `text.code`. It also records the tabular
digit advance (8.669 px at 14 px, against the proportional `1` at 6.344 —
a 2.3 px difference per digit) and the laid-out widths of reference strings:
44 plain, 13 tabular, 7 uppercase letter-spaced per style. The output is
`test/glyphs.ts`, a generated file with the constants `GLYPHS`, `CHROMIUM`
and `CALIBRATED`.

**Estimation.** `textWidth(text, style)` uppercases when
`text-transform: uppercase` is set, sums each glyph's advance at the
resolved size and weight, adds `letter-spacing × size` per glyph, and under
`font-variant-numeric: tabular-nums` uses the tabular advance for every digit.
`textStyleOf(el)` reads `font-size`, `font-weight`, `font-family`,
`text-transform`, `letter-spacing` and `font-variant-numeric` up the inline
chain — the same properties the skin writes and nothing else, so an element
the skin has not dressed estimates at the body style. A table column in its
measuring pass is as wide as its widest cell, header included
(`columnWidth(th)`), and a cell's own line excludes the values folded under it
(`ownText`).

**Tolerance.** `glyphs.test.ts` asserts every reference string at every style
estimates within **3 %** of Chromium's laid-out width: 8 styles × 64 strings.
Three percent was chosen because the smallest decision the engine makes on a
text width is the `minTextColumn` of 96 px, where 3 % is under 3 px, and
because the reference strings include the engine's own worst cases (`⋯`,
`$1,234,567,890.00`, `2026-08-30`, `SHOW 40 MORE`). A wider tolerance would
let a fit plan pass in the estimator and fail in the browser by a glyph; a
narrower one would fail on sub-pixel rounding that the browser itself does
not preserve.

`textMeasurer(charWidth)` stays for block tests: when a test is about the
priority walk, an arithmetic measurer keeps the plan readable.

## The claim catalogue

Each claim names what it catches and the blind spot the review found or left.
"Blind spot" means a wrong screen the checker will pass, not a bug.

| code | what it catches | known blind spots |
|---|---|---|
| `FIT_ROW`, `FIT_COLUMNS`, `FIT_CELL` | A fit plan the engine could not satisfy and that is *still standing* after the screen settled (read back from the `data-nisli-report` stamp, so a transient report during a re-solve is not a claim). | Only Toolbar, Table, Grid and Form plan; a block that decides by another route (Bars' label column, Columns' axis thinning, App's shell) files nothing, so its overflow is caught only by `OVERFLOW_TEXT` or not at all. |
| `OVERFLOW_TEXT` | A one-line text (`white-space: nowrap`, or a text-shaped tag) estimated wider than its box with no ellipsis to say so. The box is the element's own pinned width, else its container's; sharing a row is the fit reports' job. | Boxes ignore borders, margins, scrollbars and flex shrink; a wrapped text is never inspected; a text inside an element the estimator sees as roomy (unmounted, width 0) passes vacuously. |
| `FIGURE_TRUNCATED` | A figure — an ellipsed element whose inline chain carries `tabular-nums` and whose text has a digit — narrower than its content. 0034's "figures never truncate", now checked on Stat values, money/date cells, meters. | A figure not under `tabular-nums` (a number in a `Text` body) is a text and may truncate; a figure that wraps instead of ellipsing is not seen. |
| `UNSETTLED` | The screen was still changing (tree or reports) at the turn cap (`turns`, default 12) — a proof over a screen that has not reached a fixed point is not a proof. | A screen that oscillates with a period longer than one turn but changes nothing in `innerHTML` (a pure signal loop) is seen as settled. |
| `NAME_MISSING` | A button, link or input with no accessible name (`aria-labelledby` → `aria-label` → `<label>` → content → value → title). | The name computation covers the common cases, not the full accname algorithm (no `title` on ancestors, no `role=img` alt walk). |
| `ID_DUPLICATE` | One id on two elements. Found two Forms on one screen sharing `f-<key>` ids; Forms now carry per-instance `f<n>-<key>`. | — |
| `LABEL_MISSING` | An input inside a `<form>` without a label. | Inputs outside a form (a search field in a toolbar) are checked only for a name. |
| `DIALOG_ARIA` | A `[role=dialog|alertdialog]` without `aria-modal` or with an `aria-labelledby` that resolves to nothing or to empty text. | A dialog that is correct but *closed at mount* is never opened by `prove()`; open it in the screen factory to prove it. |
| `MENU_ITEM_ROLE` | Something interactive inside a `[role=menu]` that is not a `menuitem*`. | The keyboard sequence (ArrowDown/Home/End/Escape, focus return) is 0040's and is proven in `kernel.test.ts`, not per screen. |
| `BLOCK_ERROR` | A block whose setup failed (`data-nisli-error`). | Async failures after mount surface as console errors, which `prove()` does not spy on; `verify()` does. |
| `UNREACHABLE` | An interactive element under `[inert]` with no modal open above it, or otherwise unreachable by Tab. | Reachability by *pointer* (a control under a fixed bar) is a browser question; see `HORIZONTAL_SCROLL` and the deferred reachability round. |

The proof itself, `prove()`, adds one rule the checkers cannot: the loop
runs turns — microtask, `flushEffects()`, `remeasure()` (the
ResizeObserver pass), flush — **while a turn changed the frame's `innerHTML`
or filed a report**, before and after `settle()`, and stops at a fixed point
or the cap. `ProofAtWidth.turns` says how many it took.

## `prove()` versus `verify()`

| | `prove()` — happy-dom, in a unit test | `verify()` — Chromium, against a running app |
|---|---|---|
| Sees | the engine's inline styles, the DOM tree, the estimator's widths, reports as they are filed, the evidence stamp | real layout (`scrollWidth > clientWidth`), console and page errors, the evidence stamp and ring, focus as the browser moves it |
| Cannot see | real glyph widths (estimated), borders/margins/scrollbars, wrapping, anything after an async failure, the keyboard (no browser focus model), a dialog not opened by the factory | a block's plan (only whether a report is *standing*), any claim that needs the estimator, a screen that has not loaded (files `STILL_LOADING` instead), whether the build has evidence at all (files `NO_EVIDENCE` instead of passing) |
| Unit | a `Claim` on a block at a width | a `Finding` at a route and width: `CONSOLE_ERROR`, `PAGE_ERROR`, `BLOCK_ERROR`, `LAYOUT_REPORT`, `HORIZONTAL_SCROLL`, `NAME_MISSING`, `TAB_UNREACHABLE`, `TAB_ESCAPED_DIALOG`, `NO_EVIDENCE`, `STILL_LOADING`, `LOAD_FAILED` |
| Runs | `vitest`, milliseconds per screen, no dependency | Playwright as an optional peer, `nisli-verify --base … --routes … --widths … --open route=selector`; exit 0/1/2 |
| Is the source of truth for | a screen's correctness at width; the app's test suite | the calibration's honesty and the things happy-dom has no model for |

Neither is a screenshot. Screenshots are looked at because one wants to; no
correctness depends on one.

## The runtime evidence contract

- In dev (`engine/dev.ts`: Vite/vitest `import.meta.env`, then `NODE_ENV`,
  then dev by default — the probe core uses), `reportIf(plan, report, host)`
  stamps `host` with `data-nisli-report="CODE"` while the plan is
  unsatisfied and removes it when the plan is satisfied again.
- `report(r, host)` pushes into `window.__nisli.reports`, a ring of 200,
  and calls every `onReport` listener with `(report, host)`.
- `window.__nisli = { reports: [], dev: true }` is created **at engine
  load** in dev, not lazily on the first report, so its absence is itself
  evidence: a page without it has no stamps to read, and `verify()` files
  `NO_EVIDENCE` rather than passing on silence.
- In a production build under Vite or `NODE_ENV=production` the stamp and
  ring are compiled out. A bundle defining neither keeps them; this is the
  same trade core makes for `data-nisli-error`.
- The evidence is read by Proof and Verify, and by a person in devtools. No
  decision reads it.

## What the review changed

The first cut of this round went to review and came back **CHANGES** on six
points, all of which let a passing result mean less than it claimed. Each
was applied; each has a test.

1. **A vacuous pass against a production build.** `__nisli` was created
   lazily, so a prod page passed with nothing to say. Now created eagerly in
   dev; `NO_EVIDENCE` otherwise.
2. **Figures silently truncated.** `overflowText` skipped everything under an
   ellipsis, including Stat values and money cells. `FIGURE_TRUNCATED` was
   added; `isTextual` now includes a `DIV` with inline `white-space: nowrap`.
3. **A fixed turn count instead of a fixed point.** `turns: 3` was an
   assumption about cascade depth. Now a quiescence loop with `UNSETTLED` at
   the cap.
4. **The estimator ignored three properties the skin writes** —
   `text-transform`, `letter-spacing`, `font-variant-numeric`. Read now;
   the calibration gained tabular and uppercase strings so the 3 % test
   covers the fix.
5. **A 250 ms settle proved the skeleton.** `verify()` now waits for
   `[role=status][aria-label="Loading"], [aria-busy="true"]` to clear, else
   `STILL_LOADING`.
6. **The dialog-trap claim was narrower than its doc.** It ran only for a
   dialog open at load; `open: [{ route, selector }]` (`--open`) now clicks
   before the snapshot, and keyboard-pass errors count.

Tightening the proof then surfaced three engine facts, all fixed in the
engine: a measuring table's column is its widest cell, not its header; a
cell's own line excludes its folded values; and a real Table bug — values
folded under a `date`/`money` cell inherited `tabular-nums`, found as
`FIGURE_TRUNCATED` on Settings' backups table at 360
(`ledger-2026-08-29T06-00-00.json` folded under the Date cell). Also from
proving: the CLI preferred a stale `dist/` over source, so the first smoke
silently ran old code; `bin/nisli-verify.mjs` now prefers `src/` in a
checkout.

## Consequences

- **A screen's correctness at width is a unit test in the app.** Adding a
  screen to Ledger means adding one line to `screens`; a block change that
  breaks a screen at 360 is red before a browser opens.
- **Reports are failures, not noise** (`prove-reports-are-failures` in the
  skill) — and now so are ten other things a person used to catch by eye.
- **The estimator is a calibrated instrument**, and `pnpm calibrate` must be
  re-run when the default skin's font stack or any text style changes;
  `glyphs.test.ts` fails if it is not.
- **Evidence is part of the engine's dev surface**, alongside core's
  `data-nisli-error`: an agent driving a browser can read
  `[data-nisli-report]` without a listener.
- **`Form` ids are per-instance** (`f<n>-<key>`); anything that queried
  `#f-<key>` must query by the form's prefix. One reference in
  `.agents/skills/nisli-engine/AGENTS.md` still says `#f-<key>` and is
  flagged, not changed, by this round.
- **Three measurers coexist** — `textMeasurer(n)` for arithmetic block
  tests, `estimator(frame)` for proofs, the browser for `verify()` — and
  each is named for what it is. The test that a plan is *arithmetic* and the
  test that a screen is *correct* are different tests.

## Non-goals

- **No visual regression snapshots.** A pixel diff says "something changed",
  not "something is wrong"; the north star's bar is a claim, in data, that a
  person could otherwise only verify by eye.
- **No axe (or any accessibility-audit dependency).** The ARIA claims are
  the handful the engine's own blocks make promises about — names, labels,
  modal dialogs, menu items, reachability — checked with the same DOM read
  the estimator uses. A full accname/WCAG audit is a different tool with a
  different unit of failure.
- **No estimation of what happy-dom cannot model.** Borders, wrapping and
  real focus are `verify()`'s, and the two are kept honest by the
  calibration, not by making the estimator a layout engine.
- **No rename of the intent vocabulary in this round.** The audit's findings
  are recorded ([research](../research/engine/intent-vocabulary-audit-2026-08-30.md));
  nothing landed, because Ledger was under concurrent edit.

## Long-term plan

Intent, not commitment; each phase is entered on evidence from the last.

1. **Proof as the agent feedback loop.** An agent writing a Ledger screen
   runs `prove()` and reads claims, not screenshots; `verify()` runs in CI
   against the dev server. The next measure is whether a screen can be
   written by an agent to a green proof without a human opening a browser.
2. **The vocabulary contract lands** in a round where Ledger is not under
   concurrent edit: the audit's A1–A8 in the order it proposes, each rename
   proven by the screen proof staying green.
3. **Per-screen calibration diff** — `verify()` reports against `prove()`
   claims on the same fixture, closing 0024's condition 3 at the screen
   level rather than the glyph level.
4. **Density and input axes** (0034 phase 5) — when one block is 36 px in
   one context and 18 px in another, `prove()` takes an axis alongside
   `widths`, and the claim catalogue gains the target-size claim that
   `input: 'touch'` implies.
5. **The reachability round** (the panel's 0042): pointer reachability,
   fixed bars and sheets, which is the one class of claim neither half can
   make today.
