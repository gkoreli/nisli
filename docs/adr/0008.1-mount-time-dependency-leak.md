# 0008.1. Mount-Time Dependency Leak — Reactive Slot Tears Down Live DOM

**Date**: 2026-06-18
**Status**: Resolved — dedicated child-slot effects + reactive-slot memoization in `template.ts`
**Triggered by**: backlog-mcp `activity-panel` — clicking "Show more" reset the activity list's scroll position to 0
**Depends on**: [0008. Effect Isolation and Loop Detection](./0008-effect-scheduling-and-batching-gaps.md), [0009. Framework Defense-in-Depth](./0009-framework-defense-in-depth.md)

## Context

The original repair untracked a mount-time value probe. Issue 0012 later
removed that initial-value classification entirely: every reactive child now
creates its dedicated slot effect before reading the current value. The
historical diagnosis below remains the evidence for the isolation invariant.

ADR 0008 diagnosed an `activeObserver` leak during mount and fixed it for the
**component `connectedCallback`** path. It then asserted the leak was harmless
elsewhere "when framework patterns are followed," explicitly listing computed
views as safe:

> *Computed views — the text-binding effect reads the computed, gets the same
> cached TemplateResult, and skips re-mount.*

That assertion was wrong on both clauses. This ADR records the counterexample,
the precise mechanism, and the two-layer fix. It is a direct continuation of
the ADR 0008 thread, not a new problem — same leak, different (and more common)
entry point: a **reactive template slot** mounting a subtree, rather than a
custom element's `connectedCallback`.

## Symptom (real evidence)

`activity-panel` renders day groups → task groups; each task group shows N
operations with a "Show more" toggle backed by `expandedTaskGroups` (a
`signal<Set<string>>`). Clicking "Show more" reset scroll to the top.

Instrumenting the scroll container across the toggle produced the decisive
trace:

```
[toggle] BEFORE          { scrollTop: 1880, connected: true,  sameNode: true,  scrollHeight: 5819, childCount: 54 }
[toggle] AFTER microtask { scrollTop: 0,    connected: false, sameNode: false, scrollHeight: 0,    childCount: 54 }
```

- `connected: false, sameNode: false` — the captured `<div class="activity-list">`
  was **detached and replaced** with a brand-new node (the orphan keeps its 54
  children; `scrollHeight: 0` because it is no longer in the document).
- `mainContent` (the computed that owns `activity-list`) did **not** re-fire on
  toggle — confirmed by `console.trace` showing no interleaved recompute.

So: the entire slot subtree was rebuilt, even though the computed feeding it
never recomputed. Scroll position is collateral damage of replacing the
scrollable node.

## Root Cause: the mount-time probe read is tracked

Reactivity tracks dependencies through a single global `activeObserver`
(`signal.ts`): while an effect/computed runs, every `signal.value` read
registers that signal as one of its dependencies.

`replaceMarkerWithBinding` (`template.ts`) **probes** a signal slot's value to
decide which binding to build:

```ts
if (isSignal(value)) {
  const signalValue = (value as ReadonlySignal).value;  // ← probe, was tracked
  // ...decide: reactive slot? primitive text? array?...
}
```

This probe is only a peek — the real subscription is set up afterward inside a
**dedicated inner effect**. But the peek itself reads `.value`, and mounting
runs **inside** the enclosing reactive scope. The leak chain:

```
${mainContent} slot  →  effect A: reads mainContent.value, then mounts the tree
                          (activeObserver === A for the whole mount)
  mount activity-list subtree
    └─ nested ${toggleText} slot → replaceMarkerWithBinding probes toggleText.value
         toggleText = computed(() => isExpanded.value ? 'Show less' : `Show ${n} more`)
         isExpanded = computed(() => expandedTaskGroups.value.has(id))
              └─ activeObserver is STILL A
                   └─ A.sources gains: toggleText → isExpanded → expandedTaskGroups
```

Result: **A depends on `expandedTaskGroups`**, a signal it should never have
seen. This is the exact mechanism ADR 0008 drew in its trace
(`replaceMarkerWithBinding reads signal.value` with `activeObserver is STILL
parentNode`), only reached through a reactive slot instead of a component mount.

### Why it tore everything down

Two distinct framework defects compounded:

1. **Leak (probe tracked).** `expandedTaskGroups` entered `A.sources`.
2. **No memoization in the reactive-slot effect.** On every run, effect A
   *unconditionally* disposed `currentResults` and re-mounted — it never
   compared the resolved value to what was already mounted.

So toggling `expandedTaskGroups` (a new `Set`, so it notifies by `Object.is`)
re-triggered A; A re-read `mainContent.value` (unchanged, cached), but rebuilt
the subtree anyway → new `activity-list` node → scroll reset.

### Chain of thought — "why does the effect re-run if mainContent didn't change?"

An effect re-runs when **any** signal in its dependency set notifies — not only
the one it semantically "renders." `mainContent` correctly stayed silent
(`Object.is` guard: it never depended on `expandedTaskGroups`). The re-trigger
came entirely from the **leaked** dependency `expandedTaskGroups`, which did
change. The bug was never "a computed notified when it shouldn't" — it was "the
effect was subscribed to a signal it should never have seen."

## Decision

Fix at the framework level. Mounting a legitimate, lightweight composition (a
plain function returning `html\`...\``) must be correct — requiring everything
to be a custom element just to get `connectedCallback` isolation is not an
acceptable workaround.

### Ruling 1 — Mount must never establish dependencies (primary fix)

Wrap the probe read in `untrack()` so it cannot register dependencies on the
enclosing scope:

```ts
let signalValue: unknown;
untrack(() => { signalValue = (value as ReadonlySignal).value; });
```

The probe still returns the same value and selects the same binding; the real
subscription is still established by the inner effect. `untrack` already exists
for exactly this purpose (ADR 0008 / 0009 Gap 1 — child `connectedCallback`
isolation). This is consistent application of an existing principle, not a new
primitive.

The current implementation goes one step smaller: there is no classification
probe. All reactive children use the inner slot effect, which both owns the
signal read and supports later value-type transitions.

**Invariant**: *`TemplateResult` mounting must not contribute dependencies to an
enclosing reactive scope. Every dynamic part owns its own effect.*

### Ruling 2 — Reactive slots memoize by referential identity (defense-in-depth)

The reactive-slot effect skips work when the resolved value is unchanged:

```ts
const NOT_RENDERED = Symbol('not-rendered'); // sentinel: first run always mounts
let lastValue: unknown = NOT_RENDERED;
// inside the effect, after the liveParent guard:
if (newValue === lastValue) return;
lastValue = newValue;
```

This is the memoization ADR 0008 *assumed already existed*. It would have
blunted this whole bug class even with the leak present: a spurious re-trigger
with an identical cached `TemplateResult` becomes a no-op instead of a
destructive rebuild.

## Consequences

- **No behavior change for correct code.** A computed/signal only notifies when
  its value changes by `Object.is`; `html\`...\`` builds a fresh `TemplateResult`
  every evaluation, and array slots build fresh arrays via `.map()`. So genuine
  changes always satisfy `newValue !== lastValue` and rebuild as before. The
  guard only ever short-circuits a re-run driven by some *other* dependency —
  i.e. a leak.
- **Sentinel is mandatory.** A slot may legitimately resolve to `null`/`undefined`
  on its first run; initializing `lastValue` to a plain `undefined` would skip
  the initial mount. The `Symbol` sentinel makes the first run always render.
- **Layered safety.** Ruling 1 removes the leak at the source; Ruling 2 contains
  any future leak before it can destroy live DOM (and with it scroll/focus/
  selection/IME state). Either fix alone resolves this bug; both together close
  the class.
- **Not a "computed is for variables only" restriction.** Computed-returning-
  template is a required capability (`when()`, conditional views, view
  switching). The defect was tracking during mount, not the use of computed in
  slots. Note `toggleText` is itself a *scalar* computed and still leaked —
  restricting computeds to scalars would not have prevented this.

## Insights (distilled)

- **The single global `activeObserver` makes mount a dependency-capture hazard.**
  Any `.value` read during `mount()` — even a one-off probe — silently joins the
  enclosing effect's dependency set. Mount paths must be audited for stray
  tracked reads; today the probe was the only one (attribute/class/innerHTML
  bindings all read exclusively inside their own effects).
- **"Follows framework patterns" is not a containment boundary.** ADR 0008
  reasoned the leak was benign for `each()` (idempotent reconcile) and computed
  views (cached result + skip re-mount). The first holds; the second was
  aspirational — the skip-re-mount it relied on did not exist. Safety claims
  must be backed by code, not intended behavior.
- **An effect's trigger ≠ the effect's purpose.** Debugging stalled on "why does
  the slot rebuild when its computed didn't change?" The answer: effects fire on
  *any* dependency, and a leaked one was in the set. When an effect runs
  unexpectedly, enumerate its full `sources`, don't just inspect the value it
  appears to render.
- **Component boundaries accidentally hid this.** Because ADR 0008 untracked
  `connectedCallback`, leaks never surfaced for custom elements. Plain functions
  returning templates (cheap, idiomatic composition) had no such boundary —
  which is precisely why the framework, not the usage, had to be fixed.
- **Referential memoization is the natural backstop for the single-`activeObserver`
  model.** Since computeds already cache by `Object.is`, comparing the resolved
  value at the slot makes spurious re-triggers free.

## Validation

- `packages/core/src/invariants.test.ts` — section *"INVARIANT: reactive child
  mounting does not leak deps (ADR 0008.1)"*:
  - changing a nested slot signal does not rebuild the parent reactive slot
    (node identity preserved, nested text still updates);
  - parent computed view is not recomputed when only nested signals change;
  - nested signal leak does not reach an enclosing manual effect;
  - reactive slot does not rebuild when re-triggered with an identical value
    (memoization);
  - first render still mounts when the resolved value is `null` then a template
    (sentinel correctness).
- Reverting `template.ts` to the pre-fix version fails 4 of these 5 assertions
  (node-identity / re-trigger cases); they pass with both rulings applied.
- Full core suite: **220 passing**, `tsc --noEmit` clean.
