The Platform Caught Up

Five parallel research threads — a deep map of nisli's internals plus verified sweeps of web standards, framework internals, agent-native UI, and adoption drivers — converge on one thesis: late 2025 through early 2026 was the inflection where the browser shipped the primitives nisli currently hand-rolls, while the ecosystem settled on nisli's exact architecture (fine-grained signals, no VDOM, real DOM) and moved the frontier to async, islands, and agent legibility. The bets below are ranked by leverage; each names the nisli code or ADR it upgrades.

The Baseline inflection

Safari 26.x + Firefox 144–149 pushed Navigation API, URLPattern, Invoker Commands, anchor positioning, @scope, and same-document View Transitions into Baseline between Sep 2025 and Jun 2026.

Signals won; the frontier moved

Vue Vapor shipped, Angular went zoneless-by-default, Solid 2.0 is in beta. Signals-without-VDOM is consensus. The new table stakes: first-class async, streaming, and islands — not resumability.

The AI Matthew effect is measured

29% of shipped code was AI-generated by end of 2025, and LLMs measurably amplify mainstream frameworks. Svelte's AI-docs suite (llms.txt bundles + analyzing MCP server) is the documented counter-playbook.

01Adopt Node.moveBefore() — the one-line win

Chrome 133 · Feb 2025 Firefox 144 · Oct 2025 Safari: positive, not shipped

Atomic, state-preserving DOM moves: iframe state, focus, selection, CSS animations, and popover state all survive a reparent — impossible with insertBefore. React holds it behind an experimental flag and htmx already ships it; a no-VDOM framework gets it in one feature-detected line because there is no reconciler abstraction in the way.

In nisli: keyed each() and portal currently reorder with insertBefore (template.ts:1120). ADR 0030.2 §3 already specifies this exact adoption (~10 lines, plus an empty connectedMoveCallback on the base class) and notes it completes ADR 0023's move-resilient lifecycle "on the platform's terms." It was simply not in Wave 1. Promote it to the front of Wave 2; keep deferred teardown as the fallback.

02Rebuild @nisli/ui overlays on the platform stack

Popover: widely available Oct 2026 Invoker Commands: Baseline Dec 2025 Anchor positioning: all engines since Firefox 147 dialog closedby: Safari gap · Interop 2026

The top layer plus CSS anchor positioning makes the entire hand-rolled overlay stack — floating.ts (a mini Floating-UI), portal.ts, dismissable-layer.ts, and much of focus.ts — progressively deletable. popover gives light-dismiss, stacking, and top-layer rendering with no portal machinery and no z-index management; anchor-name + @position-try gives flip/shift positioning with zero JS; closedby collapses Escape/outside-click policy to an attribute where supported.

The sleeper is Invoker Commands: custom command="--open-menu" buttons fire a CommandEvent at their target — a built-in declarative wiring channel that fits nisli's attribute-as-truth components perfectly. Teaching the component base class to listen for CommandEvent gives every nisli component a declarative API surface that plain-HTML consumers and agents can drive without any framework event binding.

In nisli: ADR 0019 already ruled "use native popover for simple overlays before adding a framework abstraction" — the UI package predates the ruling in practice. This is executing nisli's own philosophy now that the support matrix allows it. Per-component migration (tooltip → dropdown → dialog), feature-detected, keeping the JS fallback for the Safari-shaped holes (closedby, popover=hint) that Interop 2026 explicitly targets. Interest Invokers (interestfor, Chromium-only) are the progressive-enhancement future for tooltips — watch, don't depend.

03Move the router to Navigation API + URLPattern

Navigation API: Baseline Jan 13, 2026 URLPattern: Baseline Sep 15, 2025 Interop 2026 focus area

ADR 0026 deferred URLPattern "until browser support and semantics fit" — that condition has now flipped: both APIs went Baseline within the last year (Safari 26.2 and Firefox 147 closed the set). A single navigation.intercept() handler replaces the popstate-plus-click-delegation pair and gets correct back/forward, traversal promises, scroll restoration, and focus semantics from the browser instead of reimplementing them.

In nisli: router.ts's delegated click listener, manual history.scrollRestoration management, and the hand-compiled matcher all shrink. Nisli's typed catalog, codecs, and managed-head layers stay — they're the differentiation; only the engine underneath swaps. Feature-detect and keep the History-API path for the roughly-two-year browser tail. This also unlocks bet 04 cleanly.

04View Transitions in both lanes — SPA flush and SSG navigation

Same-document: Baseline Oct 14, 2025 match-element + vt-class: cross-browser Cross-document: no Firefox yet · Interop 2026 Speculation Rules: Chromium-only

Same-document View Transitions are Baseline, and the 2025 extras remove the old ergonomic blockers: view-transition-name: match-element auto-names elements by identity, so keyed each() reorders can animate without nisli generating unique names, and view-transition-class styles groups of items at once. The framework move is an opt-in scheduler mode — wrap the batched flush (or a router navigation) in document.startViewTransition() — plus a documented recipe for list transitions.

In nisli: zero occurrences today; ADR 0019 named the API but never ruled on it. The SSG lane is the quiet win: cross-document View Transitions plus router-injected Speculation Rules give statically-generated nisli sites app-like instant navigation with zero runtime JS — declarative CSS and a JSON script tag, exactly nisli's brand. Runtime caveat to handle once: prerendered pages must defer effects until document.prerendering flips.

05Close the hydration gap with islands-style adopt()

Field verdict: remount is below table stakes Resumability: proven unnecessary

The framework-trends sweep is unambiguous: nobody credible ships "client remounts the page" as the only story anymore, but full resumability (Qwik) also failed to become required. The settled minimum is Astro's shape — static HTML plus independently-mounting islands with state continuity (no flicker, no lost input, no double render). That is precisely the open question nisli has already framed as ADR 0025 §17, and its named enablers (T4 stable binding positions, T3 attribute-as-truth schema) are landed or queued.

In nisli: promote www's hand-rolled replace-frame (hydrate.ts, with its WWW-14 double-render scars) into a core adopt() primitive: bind a component to prerendered DOM in place, reading initial state from attributes instead of rebuilding children. This kills the double-render bug class, makes the SSG lane a first-class product ("Astro-but-one-runtime"), and is the largest single internals investment on this list — sequence it after the quick wins, likely as its own ADR graduating 0018's useful parts without adopting its full hydration-marker machinery.

06Agent-native: the ADRs bet right — now ship while the window is open

MCP Apps: official spec Jan 26, 2026 WebMCP: Chrome 149 origin trial · Edge 147 native A11y-tree evidence: CHI 2026 A2UI: v1.0 candidate, still churning

The research validates ADR 0029/0030.x's direction with new force, and sharpens the order. MCP Apps is now an official MCP extension with ChatGPT and Claude both hosting — a sandboxed-iframe HTML resource with a postMessage JSON-RPC bridge, which is almost a description of what buildAppResource() (single-file emit, size budget) would produce. That is the highest-confidence deliverable in the whole agent-native program. WebMCP graduated from speculation to Chrome 149 origin trial and native Edge 147, with Shopify/Expedia/Target-scale pilots; the gated lib/model-context.ts experiment is correctly scoped — abstract the API churn (navigator → document.modelContext, Aug 2026) behind nisli's own seam.

Two findings upgrade existing positions. First, CHI 2026 measured agent task success falling from 78% to 42% when the accessibility tree degrades — nisli's ARIA rigor and real-DOM semantics are now an empirically measurable performance feature for the agent audience, worth stating exactly that way in nisli's marketing. Second, the adoption research confirms the Matthew-effect headwind is real and measured, and that the working counter-playbook is Svelte's: sized llms.txt bundles plus an MCP docs server that statically analyzes generated code and suggests fixes — which maps one-to-one onto nisli's planned B3/B5 (context artifacts, @nisli/mcp) and A4/A5 (template static analysis, drift linter). Crawl-time llms.txt keeps earning its "cheap build artifact, not architecture" status: AI crawlers barely fetch it. The agent-time channel is where the leverage is.

In nisli: ship order — registry manifest.json + diagnostics-to-NDJSON (already specced as B1/B2), then buildAppResource() for MCP Apps, then @nisli/mcp with the Svelte-style analyze-and-fix loop, with WebMCP kept feature-detected and never auto-registered. A2UI stays "watch, then spike" — real Google code, but v0.9 was a breaking rework; let the schema stop moving first.

07Typed server functions + Standard Schema — the missing adoption gate

Standard Schema: Zod/Valibot/ArkType interop WinterTC ECMA-429: published Dec 2025 Edge rendering as a pitch: dead

The adoption research's clearest structural finding: TanStack Start's breakout year ran on typed server functions and end-to-end type safety — and "typed routes alone" now reads as 2023-era. The gates for a credible 2026 default are typed routes plus typed server functions accepting Standard Schema validators (never a hard Zod dependency), deploy adapters for Cloudflare + Node first (aligned to the now-published ECMA-429 minimum common API), and a named auth answer — auth's absence is the explicitly-cited SolidStart blocker. Meanwhile Vercel deprecated Edge Functions and Next removed the edge runtime option: "runs at the edge" is dead as a rendering pitch, but "runs on Workers" still matters as a platform.

In nisli: the environment-neutral @nisli/router/catalog with edge/Worker matching is the right foundation — what's missing is the RPC layer on top: a serverFn()-style primitive with Standard Schema input validation, wired through the Vite plugin, plus a documented Better-Auth recipe and a Workers adapter. This is the largest ecosystem-facing bet here, and the one that moves nisli from "framework" to "thing you can start a product on Monday."

08A modern-CSS pass through @nisli/ui

@scope: Baseline Dec 2025 Style queries: Baseline mid-2026 field-sizing: Baseline Jun 2026 light-dark(): widely available Customizable select: Chromium-only

Four newly-Baseline features slot straight into a light-DOM component kit. @scope with donut scoping is the style-isolation story light DOM has been waiting for — and a direct tool against the display:contents selector-translation debt catalogued in UI-36B. Container style queries (@container style(--variant: ...)) enable CSS-only variant propagation through transparent hosts. field-sizing: content deletes autogrow-textarea JS. light-dark() plus @property modernizes theme.css into single-declaration dual-theme tokens — the pattern the Tailwind-v4 ecosystem is converging on. Customizable <select> stays progressive enhancement: layer appearance: base-select styling on the native element now, keep the ARIA listbox until Safari/Firefox ship, then delete it.

09Small runtime wins with outsized polish

using / DisposableStack: Stage 4, ES2026 scheduler.yield: Safari missing setHTML / Sanitizer: Safari missing Soft-nav metrics: Chrome 151 + web-vitals v6
  • Explicit resource management. using e = effect(...) — Safari landed it in STP this month, closing the matrix. Add [Symbol.dispose] to effect, resource, query subscriptions, and Emitter handles; near-zero bytes, real ergonomic and agent-legibility payoff (disposal becomes syntactically checkable).
  • Time-sliced flushing, opt-in. ADR 0019's rejection of scheduler-as-core stands, but scheduler.yield() is now Chrome + Firefox: a feature-detected yield point inside long flush() cascades protects INP without touching microtask semantics.
  • Narrow html:inner. The planned TrustedHTML/Sanitizer follow-up is now actionable: setHTML() shipped in Firefox 148 + Chrome 146. Feature-detect, keep raw() as the seam.
  • Instrument for soft navigations. Chrome 151 ships per-route LCP/INP for SPAs and web-vitals v6 supports it natively. Fine-grained updates are exactly what the new per-route lens rewards — wire the router to it and nisli gets favorable, measurable field data essentially for free.

10TC39 Signals: hold the line, add an interop edge

Still Stage 1 · no engine implementation Polyfill interop: Lit, Angular-adjacent

The proposal has not advanced since ADR 0015 judged it "right direction, wrong timing" — that call remains correct, and nisli's watcher-compatible flush() design keeps the forward path open. The one cheap addition: a small optional adapter (the @lit-labs/signals pattern) that lets nisli signals interoperate with polyfill-based components, which buys cross-library credibility without betting the core on a Stage 1 API.

Confirmed non-goals

  • DOM Parts: effectively dormant (no spec advancement, no implementation). Keep internal bindings part-shaped as ADR 0014 plans, but build the compiled-template work on today's platform.
  • Resumability: Qwik stayed niche; islands won. Bet 05 is the whole answer.
  • In-chat checkout protocols: OpenAI killed Instant Checkout in March; UCP is alive but platform-side. Emit clean structured data and WebMCP tools; build no commerce protocol.
  • Scoped custom element registries: shadow-root-only, as ADR 0030.2 already noted — still useless for light DOM; re-check only if the light-DOM inheritance question reopens.
  • Shadow DOM: open-stylable shadow roots remain a WICG issue with no spec. The light-DOM stance is validated through at least 2027 — and the "HTML web components" sentiment shift means it's now fashionable, not contrarian.

Sequencing

Quick wins first: 01 and the runtime items in 09 are days, not weeks, and several are already specced in ADR 0030.2. The UI platform pass (02, 08) runs as per-component migrations on the existing UI worklist cadence. The router pair (03, 04) is one coherent ADR. 06 should overlap everything — the MCP Apps window is open now and the manifest/diagnostics groundwork is already prioritized. 05 and 07 are the two genuinely large bets; 05 makes existing users' products better, 07 makes new users possible. Both deserve their own ADRs before code.
