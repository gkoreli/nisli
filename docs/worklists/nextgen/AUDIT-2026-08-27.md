# Audit — the north-star goal against what was built

**Date**: 2026-08-27 · **Status**: audit, no decisions taken · **Requested by**: Goga
**Sources**: `NEXTGEN-SCRATCHPAD.md` §0–§8, `NORTH-STAR.md`, ADR 0032, ADR 0033,
`git log -- packages/intent`, `packages/intent/src` as of `0a6dfed`, and one day
of building `packages/recipes` on the package.

## 1. The goal, in the owner's words

From §0 (2026-08-25, verbatim): *"some kinda high level building blocks so
that AI can reason and build pixel perfect UI much better than any of the
existing frameworks, like higher level engineering language/framework, so that
AI agents can iterate and build much faster and better UI, like pretty much
what React and Typescript did to JQuery, HTML and Javascript."* Later the
same day (round 10): the new package is *"everything that is going to make
sure that nisli becomes a defacto UI framework that everyone uses in a year
or so."* On 2026-08-27: *"anyone building an app should use this framework,
and should 5x the engineering velocity."*

Three properties, then: **(a)** a higher-level, typed language of building
blocks; **(b)** an engine that makes the decisions an author would otherwise
make with eyes — §0.1: *"it needs to see the whole tree, own the render, and
re-decide when things change. A library can't do any of that"*; **(c)** the
result is measured in engineering velocity, for agents.

## 2. What was built

`packages/intent` at `0a6dfed`, by line count of non-test source:

| part | lines | share | what it is |
|---|---|---|---|
| `theme/*.css` | 1,643 | 23% | the resolution table: context axes → values, in the cascade |
| `fit/` | 1,492 | 21% | measured degrade: a bounded loop plus its DOM adapter |
| `diagnostics/` | 3,427 | 47% | 16 measuring rules, the injection harness, the code registry |
| `contracts.ts`, `explain.ts`, entries | 705 | 10% | the typed vocabulary, provenance, the barrel |

Plus 2,300 lines of ADR (0032, 0033) and 13,800 lines of evidence under
`docs/worklists/nextgen/`.

Against the three properties:

- **(a) a typed language of building blocks** — *partially*. `contracts.ts`
  types ~30 words. There are no building blocks: the package ships no
  component, and the `menu` strategy's only implementation lives in a
  prototype that was deleted today (`GAPS.md` G1). The authoring surface, as
  every example in the README shows, is `data-*` attributes on `<div>`s.
- **(b) an engine that owns the tree and the render** — *no*. The engine is
  the CSS cascade (tier 1), the browser's own solvers (tier 2), and a solver
  that, by charter, *"stays ~35 lines or it becomes GSS"* (ADR 0032 §4). The
  cascade is the thing §0.1 says cannot be the engine: *"CSS decides one
  element at a time and never knows what its siblings need."*
- **(c) velocity for agents** — *never measured*. No kill criterion in §6
  mentions velocity. No round built anything with an agent and counted
  iterations. The one artefact §5.4 names as *"the comparison that travels"*
  — same prompt, same agent, nisli vs React+Tailwind, rounds until correct —
  was never run.

What was built is a **closed styling vocabulary, a stylesheet that resolves
it, a small fit loop, and a large oracle that verifies the result.** That is
a real and unusual thing. It is not the thing in §1.

## 3. Where it diverged, round by round

The drift was not one decision. It was five, each locally reasonable, each
recorded, each moving the centre of mass from *engine* to *checker*.

**Round 1–3 (2026-08-25): the checker became the frame.** The question was
split into "representation" and "oracle", and three evidence passes were
commissioned on *checking* — defect corpus, visual-oracle prior art, snapshot
formats. By round 3 the lead was *"appearance as a machine-checkable
contract"* (§5.R). The engine was not yet on the board. The prior art that
was read was Galen, axe-core, Applitools, Chromium layout baselines,
ReDeCheck — all checkers. TeX, AppKit toolbars, Auto Layout and Figma
auto-layout are mentioned once, in C11's precedent paragraph, and no evidence
pass was ever commissioned on *them*.

**Round 4–5: the owner corrected it, twice, and the correction was half
absorbed.** Round 4: *"the dead-CSS diagnostic is …"* — pushback that moved
the lead to C10 (declare, derive). Round 5: *"C10 is a component library.
Radix Themes ships that today"* — pushback that produced C11, whose text is
the closest thing in the record to §1: *"move all of them out of the author
and into the engine … it requires owning the render path, the tree, and the
reactive graph."* But C11's own feasibility paragraph, written in the same
entry, immediately fenced it: *"we do not solve general constraints and we do
not replace browser layout. Three tiers … Tier 3 is a small bounded loop."*
The engine was defined and capped in the same breath.

**§5.4 "What is actually load-bearing": the engine was demoted to 5%.** This
is the pivotal paragraph. It ranks the bet: resolution table 40%, exclusivity
25%, vocabulary 20%, verification 10%, *"the measured fit pass — one
ResizeObserver, ~25 lines — 5%"*. And states: *"The fit solver is the demo,
not the thesis … if it were removed the bet would still be a bet."* Under
§0.1 the fit solver — the part that decides across siblings — is the closest
thing to the thesis. This weighting inverted §1 and every later round built
to it.

**Round 9: constraints from core pre-shaped the package.** *"Zero runtime
deps, no build policy, no CSS, and the sub-10KB ceiling"* became the *entry*
requirement. C11 was *"split by destination"*: `fit/` and `contracts.ts`
core-shaped, `diagnostics/` dev-only, `theme/` CSS *"which core does not ship
at all, so the resolution table can never live there."* An engine that owns
the render cannot be sized to a 10KB kernel's spare bytes; the split
guaranteed the derivation logic would stay in CSS.

**Rounds 11–14 and ADR 0033: the checker ate the budget.** Once the table was
CSS, it could only be verified by measuring Chromium; once verification was
by measurement, the checker had to be sound; soundness demanded an injection
harness, fault seeding, self-tests, the obligations type. *"Eight of fourteen
defects were in the oracle."* That is honest and it is also the tell: half
the engineering effort went into making a linter trustworthy, because
nothing was deciding — only checking.

**The north star (2026-08-25) codified the result.** *"Why determinism is
the product"* lists checkable, enumerable, explainable, portable,
pre-solvable. All five are properties of a *verifier*. None is *"the engine
decided so you didn't have to"*.

## 4. Why it was built this way

Not carelessness; a method with a bias.

1. **The method selects for the measurable.** Every round's rule was
   *"measured, not asserted"*, *"primary-sourced"*, *"honest
   counter-evidence"*. A CSS table can be measured in Chromium tonight. An
   engine that owns the render is a bet that can only be measured after it
   exists. The method reliably chose the former.
2. **The prior-art search was aimed at checkers.** Its deaths (Galen, GSS,
   layout baselines) taught what to *avoid*; nothing was commissioned on what
   native toolkits *do*, so the engine had graves to fear and no living
   precedent to copy.
3. **"Not GSS" was over-generalised.** GSS died of general constraint solving
   (Cassowary) at 2014 browser speed. That argues against constraint
   solving, not against a discrete, priority-driven, tree-aware decision
   engine — which is what AppKit and Figma ship. The ruling conflated the two.
4. **Core's ceiling was applied to the framework.** ADR 0019/0030.2 minimalism
   is right for a kernel. Round 10 explicitly said core is the kernel and the
   new package is the framework — and then round 9's kernel constraints were
   kept as the package's entry bar anyway.
5. **Velocity was never a kill criterion.** So nothing ever tested the claim
   the whole programme exists for.
6. **Nobody built an app on it until today.** 240/240 cells measured the
   package alone. The first real consumer surfaced nine vocabulary gaps and
   the fact that the `menu` strategy ships no implementation, in one
   afternoon. That is the test that should have run in round 6.

## 5. What survives the audit

Not everything was wasted, and the record says exactly what to keep.

- **The vocabulary and exclusivity** (§5.4 items 2–3) survive intact: a
  closed set of ~30 typed words, no second styling channel. This *is* the
  language an agent writes in. It must become typed component props, not
  attributes — but the words are right.
- **The resolution table's *content*** survives: one unit, nested context
  axes, contrast held by construction. It must move from CSS into typed data
  the engine reads and emits — the 79.1% coverage number is evidence it can.
- **The fit solver's *idea*** survives and should become the centre: it is the
  only code that decides across siblings. It has to grow from 35 lines to an
  engine, which means the "tier 3 stays small" ruling is the one ADR 0032
  decision that has to be reversed.
- **The checker shrinks.** Every rule that exists because the engine did not
  decide (crushed, overflow, viewport, reflowed, shredded, clipped-loss,
  multicolumn, truncation, competing-primaries) becomes either unrepresentable
  or an engine assertion. What remains is the escape-hatch guard (N601), the
  vocabulary guard (N610), contrast (N640), hit-target (N650) — checks on
  inputs, not on outcomes.
- **The evidence** survives as a warning label: what was measured about
  aesthetics, APCA, Hick's law, model disobedience, Polaris, Spectrum and
  Tailwind is all still true and all still constrains the engine's design.

## 6. The one sentence

The programme set out to build a framework whose engine makes the decisions
that need eyes, and — through an evidence method that rewards what can be
measured today, a "not GSS" ruling that capped the engine at 35 lines, and a
kernel byte ceiling applied to a framework — built a styling vocabulary with
a stylesheet and a verifier instead. The words are right; the engine was never
started.

## 7. Not decided here

Whether to start it; what it decides and what it delegates; how it avoids
Cassowary; where core must open seams for it (round 10 said the dependency is
bidirectional — that was the right call and it was never used); and what the
first velocity measurement is. Those are the next ADR, not this audit.
